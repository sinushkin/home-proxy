# tests — проверка setup/*.sh на чистых системах (Docker)

Поднимает в Docker «свежие VPS» и клиентов (systemd + sshd) и прогоняет на них `setup/*.sh`
так, как это делает человек: у серверов и клиентов есть только **root/пароль** (или пользователь
`testuser` с паролем и sudo), ключа нет — первым шагом `setup/ssh-key.sh` кладёт ключ.

| Роль | Системы |
|---|---|
| сервер (`vps-server`) | Debian 12, Debian 13, Ubuntu 24.04, Ubuntu 22.04 |
| клиент (`vps-client`) | Debian 13, Manjaro |

(«Ubuntu 24.06» не существует — взяты 24.04 и 22.04; список — в `docker-compose.yml`.)

## Запуск

```bash
tests/run.sh                          # все пары сервер × клиент
tests/run.sh -s debian12 -c debian    # одна пара
tests/run.sh -p мой-проект --keep     # свой compose-проект; не гасить контейнеры после прогона
tests/run.sh --down [--purge]         # остановить и удалить контейнеры (--purge — ещё и кэш пакетов)
APT_PROXY=http://192.168.3.2:3142 tests/run.sh     # свой кэш apt вместо локального
```

Нужны: `docker` + compose, `sshpass`, `cargo` (скрипты setup собирают бинарники на этой машине),
права на `docker` без sudo. Выход ненулевой, если хоть одна проверка провалена.

## Что проверяется

На каждом сервере: `ssh-key.sh` (пароль → ключ), `vps-prepare.sh`, `vps-server.sh` — служба
`hp-vps-server` активна, `ip_forward=1`, NAT есть, повторный `vps-server.sh` ничего не меняет.
На каждой паре: `vps-client.sh` — GUID клиента в `clients.txt`, служба `hp-vps-client` активна,
в работе ≥ 4 дыр, пинг `10.94.0.1` через туннель, маршрут по умолчанию уходит в `hp0`, `curl http://example.com`
(DNS + TCP в интернет через туннель и NAT сервера).

## Устройство

- Сеть `172.29.77.0/24` (серверы .11–.14, клиенты .21–.22). Адрес хоста (.1) лежит в этой же
  подсети, поэтому полный туннель клиента (`/1`-маршруты) не рвёт ssh с хоста.
- Контейнеры `privileged` (TUN, iptables, sysctl, systemd). На хосте ничего не меняется.
- `tests/out/` (в `.gitignore`): свой ssh-ключ, конфиг и обёртка `ssh` в `PATH` на время прогона —
  `~/.ssh` и ваши алиасы не затрагиваются. Состояние скриптов (`setup/state/*172.29.77.*`) удаляется
  в начале и в конце.
- Кэш пакетов: `apt-cacher-ng` (профиль `proxy`, том `apt-cache`, порт `172.17.0.1:3142`; адрес — `PROXY_BIND`).
  Образы собираются через него (`host.docker.internal`), в готовых образах прокси не остаётся. Manjaro
  (`pacman`) через apt-cacher-ng не кэшируется — образ собирается один раз и потом берётся из кэша слоёв.

## Чего нет

- **Windows** в Docker не запустить. `setup/win/*.bat` проверяются на ВМ `win` вручную (`setup/win/README.md`).
- Роутер OpenWrt (mipsel): нужен настоящий роутер или QEMU, здесь не эмулируется.
- Ubuntu/Debian — только `x86_64`.
