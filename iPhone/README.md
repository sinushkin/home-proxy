# iPhone — что нужно и почему пока отложено

**Статус: не делаем.** Решение принято после оценки трудоёмкости: для iPhone слишком
много условий вне кода (Mac, платный аккаунт Apple, устройство, ограничения iOS).
Ничего из перечисленного ниже не сделано: ни кода, ни проекта Xcode. Этот файл
фиксирует, что выяснилось, чтобы не разбираться заново, если вернёмся к теме.

Идея та же, что у Android (`../android-vpn`): телефон держит 10 UDP-дыр с keep-alive до
сервера на ПК (`../server`), а трафик WireGuard идёт через локальный мост
в эти дыры. Нужен был бы отдельный GUID для iPhone (Android остаётся со своим).

## Что нужно для разработки под iPhone

| Что | Зачем / комментарий |
|---|---|
| **Mac и Xcode** | Приложения для iOS собираются и подписываются только в Xcode на macOS. Из Linux собрать и подписать нельзя. Xcode бесплатный, около 40 ГБ, версия macOS должна подходить под версию Xcode |
| **Платный Apple Developer Program** (около 99 $ в год) | VPN на iOS делается через Network Extension, а разрешение (entitlement) на него бесплатный Apple ID не получает |
| **Реальный iPhone и кабель** | Network Extension в симуляторе не работает. На телефоне включается Developer Mode (iOS 16 и новее), сертификат разработчика подтверждается в настройках |
| **Swift, SwiftUI** | приложение и расширение; Rust остаётся для ядра |
| **`wireguard-apple` (WireGuardKit)** | WireGuard для iOS как Swift-пакет; собирает `wg-go`, поэтому на Mac нужен Go |
| **Rust-таргет `aarch64-apple-ios`** | ядро (`hp-client`) собирается на Mac в статическую библиотеку и подключается через C-интерфейс; кросс-компиляция с Linux без Apple SDK не годится |

## Как это устроено в iOS (отличия от Android)

- На Android VPN — `VpnService` внутри приложения. На iOS нужны **приложение и отдельное
  расширение `Packet Tunnel Provider`** (свой процесс). В расширении жили бы наш клиент
  (10 дыр, мост на `127.0.0.1`) и WireGuard.
- Приложение и расширение обмениваются данными через **App Group**; в `entitlements`
  нужны `Network Extension (packet-tunnel-provider)` и App Group.
- Трафик самого расширения идёт мимо его же туннеля (аналог `ExcludedApplications`).
- Порядок «сначала дыры, потом VPN» сохраняется: `startTunnel` запускает клиента, ждёт
  хотя бы одну живую дыру и только потом настраивает туннель.
- У расширения жёсткий лимит памяти (порядка 50 МБ, зависит от версии iOS). Наш клиент
  небольшой (на Android `.so` 1–2 МБ), но проверять нужно на устройстве.

## Проблемы, из-за которых тему отложили

1. **Нужен Mac.** Есть виртуалка `OSX-KVM`, и технически собирать в ней можно.
   Но лицензия Apple разрешает macOS только на технике Apple, а сама виртуалка на
   произвольном железе часто нестабильна (обновления, подпись, USB-проброс iPhone).
2. **Платный аккаунт.** Без Apple Developer Program Network Extension недоступен, а значит,
   VPN сделать нельзя вообще. С бесплатным Apple ID профиль живёт 7 дней и без
   расширения. Оплатить программу российской картой обычно нельзя.
3. **Нельзя проверять без устройства.** Симулятор не поддерживает Network Extension, значит
   каждый цикл правки идёт через сборку, подпись и установку на реальный iPhone.
4. **Сеть.** iPhone у оператора и на точке доступа сидит за симметричным NAT (порт зависит
   от адресата), с которым обычный пробив у нас не справляется (см.
   `../wireguard/README.md`, п. 7). Эта проблема общая с Android и от платформы не зависит.
5. **Ограничения iOS.** Лимит памяти расширения, запрет на часть фоновой работы, повторная
   подпись и проверки Apple при раздаче через TestFlight.

## Что можно было бы сделать без Mac (не сделано)

- **ПК.** Второй экземпляр `homeproxy-server` для iPhone со своими `MY_ID` и `PEER_ID`
  (GUID'ы должны отличаться от пары Android, иначе брокер вытеснит клиента с тем же
  `client_id`) и второй пир в WireGuard (`10.77.0.3`) с отдельными ключами. Для этого
  `../wireguard/gen.sh` нужно научить генерировать набор для второго устройства.
- **Rust.** Собрать `hp-client` как статическую библиотеку с C-функциями (`start`, `stop`,
  `status`, `live_holes`) и проверить на хосте.
- **Swift.** Исходники приложения и расширения можно было бы написать, но собрать и
  проверить их без macOS нельзя.

## Если вернёмся к теме

1. Решить вопросы 1–2 выше (Mac и платный аккаунт).
2. Сделать «ПК» и «Rust» из списка выше (они не зависят от Mac).
3. На Mac: проект Xcode с приложением и `Packet Tunnel Provider`, `wireguard-apple`,
   статическая библиотека Rust, App Group и entitlements, установка на iPhone.
4. Проверять на сети без симметричного NAT (обычный домашний Wi-Fi другого
   провайдера).
