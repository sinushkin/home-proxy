# vps-relay

Релей VPS-сервера: для клиентов (`vps-client`, `hp-router`) — ещё один такой же сервер, поток
делится по дырам между двумя адресами. Сам релей пакеты не разбирает и ключей клиентов не знает:
перекладывает их на настоящий сервер, подпись — сквозная клиент ↔ сервер.

К серверу релей приходит сам — как VPS-клиент по своему GUID, с белого или серого адреса; сервер
никуда не ходит. Клиенты узнают о релеях от сервера (`RelayOffer` раз в минуту) и ведут через них
долю новых дыр; пока разрешения нет — ходят только напрямую. Схема обмена — `connection::vps::relay`.

## Сервер

`relays.txt` рядом с `vps.env` (или `RELAYS_FILE`) — GUID релеев, по одному на строку; читается при
запуске. Имя релея (первая группа GUID) не должно совпадать с именем клиента. Доля новых дыр
клиентов через релеи — `VPS_RELAY_SHARE` (%, по умолчанию 50).

## Релей

Настройки — окружение (для systemd — `EnvironmentFile`):

```
VPS_SERVER=203.0.113.10:40600       # порт знакомства сервера
MY_ID=<GUID релея>
SERVER_ID=<GUID сервера>
RELAY_PUBLIC_IP=203.0.113.20        # белый адрес для клиентов; без него — как видит сервер
RELAY_BOOTSTRAP_PORT=40600          # порт знакомства для клиентов (40000)
RELAY_PORTS=40601-40699             # порты сессий (40001-49999)
```

Брандмауэр релея должен пропускать входящий UDP на порт знакомства и `RELAY_PORTS`. Клиентам
ничего настраивать не нужно (нужна версия, которая понимает `RelayOffer`; прошлые его пропускают);
адреса релеев клиент сам пускает мимо туннеля.
