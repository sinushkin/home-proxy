# openwrt-k-router — обвязка роутеров OpenWrt вокруг vps-client и hp-router

Всё, что стоит на роутере вокруг туннеля, кроме самих бинарников (их собирает `OpenWRT/build.sh`,
ставит и настраивает `setup/`).

## Что здесь
- `udp-direct/` — UDP из LAN напрямую через WAN (торренты, игры), остальной трафик — в туннель.
  Идея взята из старого проекта клиента 104 (OpenVPN): метка на UDP с локальных портов, отдельная
  таблица маршрутов с WAN-шлюзом. Отличия от старого варианта:
  - туннель — `vps-client` (интерфейс `hp0`, маршруты `/1` ставит сам клиент), а не `tun1`;
  - правила fw4 не сбрасываются (`nft flush ruleset` в старом скрипте стёр бы их);
  - правила метки — в своей таблице `inet hp_udp`, маршрутизация — в таблице `200`.
- `direct/` — раздельное туннелирование: адреса, которые идут мимо VPN напрямую через WAN
  (например, российские сервисы, банки). Список свой на каждом роутере, в git не хранится:
  `/etc/vps-client/direct-list.txt` (образец — `direct/list.txt.example`). `up.sh` ставит набор
  `inet hp_direct`: пакеты на эти адреса получают метку `0x2` и уходят по таблице `200` (WAN), как и UDP
  напрямую. Нужен уже поднятый `udp-direct/up.sh`. Набор проверяется `nft -c` без применения;
  в списке — адреса и CIDR.
- `clients/_template/` — что нужно на каждый роутер и что нельзя переносить из старых архивов.

## Как работает UDP напрямую
1. Пакет из `br-lan` с UDP на порт из `UDP_DIRECT_PORTS` получает метку `0x2` (prerouting, до выбора маршрута).
2. `ip rule fwmark 0x2 lookup 200` (приоритет 1000, раньше `main`) отправляет его в таблицу 200: default — через WAN.
3. Всё остальное идёт по `main`: туннельные `/1` через `hp0`, default — WAN. Адрес сервера уходит через WAN
   по `/32`, который ставит сам `vps-client`.
4. NAT на WAN уже есть: зона `wan` в fw4 с `masq`.

## Деплой
`openwrt-k-router/deploy.sh <роутер>` копирует скрипты на роутер в `/etc/vps-client/` (и список
раздельного туннелирования, если задан `DIRECT_LIST_FILE`). Туннель и правила не трогает, они
применятся при следующем перезапуске службы. `DRY_RUN=1` — только напечатать действия. Запускать
после `setup/vps-client.sh`. Хуки `vps-client` (из `setup/vps-client-hooks`) уже вызывают эти
скрипты, если они установлены.

## Подключение к vps-client
`vps-client` вызывает хук `/etc/vps-client/on-tun-up.sh` при подъёме туннеля и `on-tun-down.sh` при
остановке. Чтобы включить UDP напрямую, добавить в эти хуки:

```sh
# в on-tun-up.sh (после DNS)
[ -x /etc/vps-client/udp-direct/up.sh ] && /etc/vps-client/udp-direct/up.sh
# в on-tun-down.sh
[ -x /etc/vps-client/udp-direct/down.sh ] && /etc/vps-client/udp-direct/down.sh
```

Копия каталога `udp-direct/` — в `/etc/vps-client/udp-direct/` (делает `deploy.sh`), параметры — в `env` рядом с ним.
Для раздельного туннелирования — то же самое с `direct/up.sh` и `direct/down.sh` (после `udp-direct`).
Пока эти строки в хуки не добавлены (`setup/vps-client-hooks/` их не содержит), скрипты ничего не делают.

## Что не перенесено из старого проекта
- Установка прошивки через эксплойт (`install.txt`): не копируем, ставим OpenWrt штатным `sysupgrade`.
- OpenVPN (`tun1`, `openvpn-*` пакеты, `do.ovpn`), SSH-туннели `sshtunnel`.
- Все адреса, пароли, ключи и бэкапы из `clients/104`.
