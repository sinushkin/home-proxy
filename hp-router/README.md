# `hp-router` — роутер OpenWrt: дом через VPS и телефоны

Один бинарник (~2 МБ на mipsel) с двумя ролями:

1. **Шлюз дома.** Поднимает TUN `hp0` и динамический набор дыр (4–10 в работе, срок жизни
   `HOLE_AGE`, по умолчанию 3–10 минут) к [`vps-server`](../vps-server/README.md) с белым IP
   (как [`vps-client`](../vps-client/README.md)): весь трафик LAN и Wi-Fi уходит к VPS как
   есть, TCP — с номером в потоке, VPS возвращает порядок.
2. **Пир для телефонов.** Для каждого телефона (`PHONE_<n>_*`) — свой динамический набор P2P-дыр
   (STUN + MQTT, как у [`hp-server`](../hp-server/README.md)). Пакеты телефона роутер не
   разбирает и порядок им не восстанавливает: перекладывает в дыры к VPS как
   `WrappedData { client_id: n }` с номерами телефона, ответы VPS для `n` — обратно телефону.
   TUN и стек ядра роутера пакеты телефонов не проходят.

```
LAN/Wi-Fi -> hp0 -> hp-router ==10 дыр==> vps-server -> hp0 -> NAT -> интернет
телефон n ==P2P-дыры==> hp-router ==дыры к VPS, WrappedData{n}==> vps-server
```

Раньше на этом месте был `router`: релей телефоны ↔ домашний ПК для WireGuard (роутер
оборачивал датаграммы WireGuard, ПК их расшифровывал). От WireGuard отказались — на MT7628 он
давал 10–12 Мбит/с против 21–32 без него (`../OpenWRT/Tun.md`, `../Performance.md`).

## Запуск

```sh
hp-router [--config router.env]     # без --config: router.env рядом с бинарником
hp-router --config … --connection-string       # строка подключения трея
hp-router --config … --new-connection-string   # новый ключ: прежние строки перестают работать сразу
```

Постоянная установка на роутер (флеш): бинарник — `/usr/bin/hp-router`, настройки и состояние —
`/etc/hp-router/` (`router.env`, `ca.crt`, `control.key`, `phones.state`), служба procd —
`/etc/init.d/hp-router` (из [`../OpenWRT/luci-app-homeproxy`](../OpenWRT/luci-app-homeproxy/)):
`/etc/init.d/hp-router start`, автозапуск — `enable`. Логи — `logread -e hp-router`.
Маршруты (`ROUTES=auto`: `0.0.0.0/1` и `128.0.0.0/1` в `hp0`, `/32` до VPS, STUN и MQTT через
аплинк) служба ставит сама; перезагрузку firewall после запуска (flowtable) пока ставят руками
(`../OpenWRT/Tun.md`). Замена `vps-client` на `hp-router` (хуки DNS и раздельное туннелирование
остаются те же, `ON_TUN_UP`/`ON_TUN_DOWN` можно задать абсолютными путями) — см. «Проверено».

**Трей и LuCI.** С `CONTROL_ADDR=<адрес LAN>:47001` роутер слушает протокол управления
([`../control`](../control/README.md)): трей на ПК показывает VPS и телефоны с дырами и потерями,
добавляет телефон по QR (роутер сам заводит пару GUID и свободный номер телефона; после
первого подключения телефон сохраняется в `phones.state`) и удаляет сопряжённые. Строку
подключения трей получает один раз от пользователя: LuCI → Службы → Home Proxy → «Скопировать»
(там же «Новая строка подключения», если строка утекла или забыта).

Настройки — [`router.env.example`](router.env.example): VPS (`VPS_SERVER`, `VPS_MY_ID`,
`VPS_PEER_ID`), рандеву для телефонов (`STUN_ADDR`, `MQTT_ADDR`, `MQTT_CA`) и пары GUID
телефонов. Телефонов может не быть — тогда только шлюз. Адрес в туннеле и DNS роутеру и его
телефонам выдаёт VPS (запросы телефонов роутер пересылает с их номером). Нужны root,
`kmod-tun`, маршрут по умолчанию в `hp0` только для LAN (сам роутер ходит через WAN) и
перезагрузка firewall после каждого запуска (flowtable) — по шагам в
[`../OpenWRT/Tun.md`](../OpenWRT/Tun.md).

В логе раз в 30 с (при изменении): дыры к VPS, пакеты из TUN и в TUN, по телефонам — число живых
дыр, пересылка к VPS и к телефонам с потерями.

## Проверено

**`o1`, 2026-10-10: `hp-router` вместо `vps-client`** (домашний шлюз, OpenWrt 22.03, MT7621,
mipsel, 2,36 МБ; настройки `/etc/hp-router/router.env` собраны из `vps-client.conf`, ключ управления
и хуки прежние, автозапуск включён, `vps-client` выключен, бинарник оставлен для отката): VPS
8–10/10 дыр, интернет и DNS без перерыва (простой при замене ~40 с, замена скриптом с откатом).
Телефон (хотспот iPhone) через роутер: сопряжение — `hpctl pair` и ссылка в приложение, 9–10/10 дыр,
адрес `10.94.0.6` от VPS, TCP 16.8 Мбит/с одним соединением и 19.7 четырьмя, ротация дыр на обоих
участках без потерь по метрикам дыр. Пинг телефона по цепочке телефон → роутер → VPS: RTT 216–260 мс
(у самого роутера до VPS и дальше ~100 мс), потери в трёх прогонах 3.7%, 7.7%, 0% — на всех дырах
телефон→роутер одинаково ~3% (радиоканал), на участках роутер↔VPS и роутер↔телефон по метрикам 0%.

**Раньше (стенд `jump1`, 2026-09):**

С управлением (размер 2 101 608 байт против 1 970 508 без него, +128 КБ): роутер под procd из
`/usr/bin` + `/etc/hp-router`, VPS 10/10; трей с ПК (через ssh-туннель к LAN) — первая вставка
строки, статус VPS и телефонов; «Добавить телефон» → `hp-client` на VPS с GUID из пакета →
сопряжён с роутером (номер 2), адрес `10.80.1.2` выдал VPS; новая строка подключения — трей со
старой сразу получает отказ, с новой подключается без перезапуска; права LuCI проверены сессией
rpcd (показать — можно, сменить ключ без права записи, чужой конфиг или команду — нельзя).

Xiaomi Mi Router 4C (OpenWrt 23.05.4) ↔ VPS: дом ~25 Мбит/с в каждую сторону (TCP, iperf),
телефон на LTE через роутер — 14/7 Мбит/с (speedtest), дыры 10/10 на обоих участках.
Сквозной тест «телефон за роутером → VPS → обратно» без сети — `cargo test -p hp-tun`
(`phone_packets_behind_the_router_reach_the_vps_tun_and_come_back`).

Сборка под OpenWrt — [`../OpenWRT/README.md`](../OpenWRT/README.md).
