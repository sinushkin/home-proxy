# control — управление home-proxy: трей, сопряжение по QR

Три части:

- **`hp-control`** (этот крейт) — протокол управления: сообщения (`proto/control.proto`),
  кадрирование, токен, клиент, ссылка сопряжения для QR. Сервер протокола живёт в самой службе
  (`hp-server/src/control.rs`).
- **`hp-tray`** (`tray/`) — трей для Windows и Linux на Slint: значок с цветом состояния, окно со
  статусом службы, телефонами, дырами и потерями, добавление телефона по QR.
- **`hpctl`** (`src/bin/hpctl.rs`) — то же из консоли, без графики: `status`, `pair`, `remove <имя>`.

Службы остаются самостоятельными: их можно настраивать вручную (`server.env`) и запускать без
трея. Связь одна — TCP-протокол управления.

```
hp-tray / hpctl  --TCP 127.0.0.1:47001, токен-->  hp-server  --10 дыр-->  телефоны
```

## Протокол

Кадр: `u32` (big-endian, длина) + protobuf `ControlMessage` (`oneof`), тот же `prost`, что и в
`connection`. Первое сообщение клиента — `Hello { token, version }`, ответ — `Welcome`; с неверным
токеном служба молча закрывает соединение. Дальше:

| Запрос | Ответ |
|---|---|
| `GetStatus` | `Status`: режим, `BIND_ADDR`, время работы, трафик моста, пиры (имя, состояние, живые дыры, адреса в туннеле, дыры с адресом пира, счётчиками и потерями в обе стороны, «ждёт первого подключения», можно ли удалить) |
| `Subscribe { interval_ms }` | служба сама присылает `Status` раз в `interval_ms` (трей — раз в секунду), пока соединение открыто |
| `CreatePairing` | `Pairing { bundle, uri, name }` — пакет сопряжения нового телефона |
| `RemovePeer { name }` | `Done` или `Error` |

Полные GUID в статус не попадают — только имена (первая группа GUID): полный GUID — секрет пары.
Номера 5–8 и 11 (`Event`, `Identity`, `SetPeer`, `Restart`) зарезервированы в замысле.

**Потери** считаются по обмену `Stats` между пирами (раз в 10 с): пир сообщает, сколько по
дыре отправил и получил, служба сравнивает со своими счётчиками на момент отчёта. Меньше 20
пакетов по дыре — оценки нет («—»).

**Почему без шифрования.** Канал работает в «демилитаризованной зоне»: служба слушает только
loopback (`CONTROL_ADDR`, по умолчанию `127.0.0.1:47001`; на роутере — адрес LAN, не `0.0.0.0` и
не WAN). XOR, как у дыр, тут дал бы лишь ложное чувство защиты. Защита:
- доступ — по токену (`control.token` рядом с настройками службы: 32 случайных байта в hex,
  создаётся при первом запуске, на Unix с правами 600); сравнение в постоянном времени, токен
  не пишется в лог;
- в LAN трафик управления виден другим узлам, поэтому сегмент должен быть доверенным. Если
  понадобится иное, поверх добавляется TLS, формат сообщений не меняется.

## Сопряжение

«Добавить телефон» (трей) или `hpctl pair`: служба генерирует новую пару GUID (свой и телефона),
сразу поднимает для неё набор дыр и отдаёт пакет:

```proto
message PairingBundle {
  uint32 version = 1;
  string pc_guid = 2;        // GUID службы — PEER_ID телефона
  string phone_guid = 3;     // GUID телефона — MY_ID телефона
  string stun = 4;           // ip:порт[,ip2:порт]
  string mqtt = 5;           // ip:порт, TLS
  bytes mqtt_ca_pem = 6;     // ca.crt брокера
  reserved 7;                // было: конфиг WireGuard
  uint64 expires_unix = 8;
}
```

QR — ссылка `homeproxy://pair?d=<base64url(PairingBundle) без =>` (~1 КБ; уровень коррекции M,
поле 4 модуля). Её же можно открыть как deep link. Адрес в туннеле и DNS в пакет не входят:
телефон получает их от службы при подключении (`AddressRequest`/`AddressAssign`).

Внутри — полные GUID пары, из них выводятся все ключи, поэтому пакет — **секрет**: показывается
только по кнопке, не логируется и не пишется на диск; трей стирает картинку при закрытии.

Жизненный цикл на стороне службы (`hp-server/src/service.rs`):
- ожидающий телефон — не больше одного: повторное «Добавить телефон», пока он не подключился,
  выдаёт тот же пакет с продлённым сроком (10 минут), лишние наборы дыр не копятся;
- первая живая дыра — телефон сопряжён: пара дописывается в `peers.state` (права 600) и
  поднимается при каждом запуске;
- срок вышел, а телефон не пришёл — набор дыр останавливается;
- `RemovePeer` — набор дыр останавливается, адреса телефона освобождаются в мосту, пара
  стирается из `peers.state`. Пиров из `server.env` так удалить нельзя — только там.

`hp-server` может стартовать вообще без пиров (без `MY_ID`/`PEER_ID`): поставил, открыл трей,
добавил телефон.

## Трей (`hp-tray`)

```
hp-tray [--addr ip:порт] [--token-file путь] [--hidden]
```

- адрес — `--addr`, `HP_CONTROL_ADDR` или `127.0.0.1:47001`;
- токен — `--token-file`, `HP_CONTROL_TOKEN_FILE`, `control.token` рядом с `hp-tray`, `control.token`
  в текущем каталоге. На Windows проще всего положить `hp-tray.exe` рядом с `hp-server.exe` и
  `server.env`. На Linux, если служба работает от root, токен нужно сделать читаемым для
  пользователя трея (или скопировать);
- `--hidden` — не показывать окно при старте (автозапуск): окно открывается из значка.

Окно: цветная точка и заголовок («На связи телефонов: 1 из 1»), режим, `BIND_ADDR`, время
работы, трафик моста; карточка на каждый телефон (состояние, `живые/10` дыр, адрес в туннеле,
средние потери ↑ к телефону и ↓ от него; по щелчку — таблица дыр: адрес телефона, отправлено,
получено, потери, цвет — по худшим потерям: до 2 % зелёный, до 10 % жёлтый, дальше красный;
кнопка «Удалить телефон» с подтверждением). «Добавить телефон» — экран с QR и отсчётом срока;
когда телефон подключится, подпись станет зелёной.

Значок: серый — нет связи со службой, красный — ни один телефон не на связи, жёлтый — телефонов
нет или не все дыры открыты, зелёный — все телефоны на 10/10. Подсказка — телефоны и дыры. Меню:
«Открыть», «Добавить телефон», «Выход». Закрытие окна прячет его в трей.

Устройство:
- окно — Slint (`ui/main.slint`), `winit` + программный рендер: работает без GPU (ВМ, RDP);
  тема — светлая или тёмная, как в системе;
- значок: Linux — `ksni` (StatusNotifierItem по D-Bus, без GTK; KDE, XFCE, GNOME с расширением
  AppIndicator), Windows — `tray-icon`;
- сеть — tokio в фоновых потоках: подписка на статус (переподключение каждые 2 с) и отдельные
  соединения на команды; интерфейс обновляется через `upgrade_in_event_loop`, строки списка — на
  месте (иначе Slint пересоздаёт карточки и сбрасывает их состояние);
- QR — крейт `qrcode`, картинка рисуется в памяти.

Размер: ~21 МБ на Linux (без отладочной информации), ~14 МБ на Windows — почти всё Slint и winit.

## Проверено

- Linux (KDE Plasma, Wayland и X11): служба без пиров → трей → «Добавить телефон» (из меню
  значка через D-Bus) → QR с отсчётом → `hp-client` на VPS с GUID из пакета → «подключён», 10/10
  дыр; перезапуск службы — телефон поднимается из `peers.state`; таблица дыр с потерями под
  трафиком; удаление с подтверждением (сокеты набора закрываются, телефон теряет дыры); служба
  остановлена — серый значок и «Нет связи со службой».
- Windows 10: сборка `hp-server`, `hp-tray`, `hpctl`; протокол управления (`hpctl status`,
  `pair`) против `hp-server.exe` с полным туннелем OpenVPN. Окно и значок на Windows вживую не
  проверялись: на тестовой ВМ нет интерактивного сеанса.
- Тесты: `cargo test -p hp-control` (кадры, base64url, ссылка, токен), `-p hp-server --test control`
  (токен, статус, подписка, ошибки), `-p hp-tray` (форматирование, уровни, значок).
