# control — управление home-proxy: трей, сопряжение по QR

Части:

- **`hp-control`** (этот крейт) — протокол управления: сообщения (`proto/control.proto`),
  защищённый канал (`secure.rs`), общий сервер (`server.rs`, его поднимают `hp-server` и
  `hp-router`), клиент, строка подключения, ссылка сопряжения для QR.
- **`hp-tray`** (`tray/`) — трей для Windows и Linux на Slint: значок с цветом состояния, окно со
  статусом службы, телефонами, дырами и потерями, добавление телефона по QR.
- **Службы, к которым подключаются трей и `hpctl`:** `hp-server` (и `vps-server`), `hp-router`, `vps-client`
  (у последнего один «пир» — VPS-сервер; `CONTROL_ADDR`, `vps-client --connection-string`).
- **`hpctl`** (`src/bin/hpctl.rs`) — то же из консоли, без графики: `status`, `pair`, `remove <имя>`.
- **`luci-app-homeproxy`** ([`../OpenWRT/luci-app-homeproxy`](../OpenWRT/luci-app-homeproxy/)) —
  страница LuCI роутера: показать и скопировать строку подключения, выпустить новую.

Службы остаются самостоятельными: их можно настраивать вручную (`server.env`) и запускать без
трея. Связь одна — TCP-протокол управления.

```
hp-tray / hpctl  --TCP, шифр ключом строки-->  hp-server (127.0.0.1:47001)  --дыры-->  телефоны
                                              hp-router (192.168.1.1:47001) --дыры-->  телефоны, VPS
                                              vps-client (192.168.1.1:47001) --дыры-->  VPS
```

## Строка подключения

`homeproxy-control://<ip:порт>/<ключ>` — адрес службы и ключ канала (32 случайных байта,
base64url). Ключ создаёт и хранит служба (`control.key` рядом с настройками, права 600), строку
показывает по запросу:

- ПК: `hp-server --connection-string` (`--new-connection-string` — новый ключ);
- роутер: LuCI → Службы → Home Proxy → «Скопировать» / «Новая строка подключения» (или
  `hp-router --config /etc/hp-router/router.env --connection-string`).

Пользователь вставляет строку в трей один раз при первом запуске (потом — кнопка «Служба…»);
трей проверяет её подключением и хранит в своих настройках (`~/.config/home-proxy/tray.conf`,
на Windows `%APPDATA%\home-proxy\tray.conf`, права 600). По файлам службы трей не ходит — так
одинаково работает и с ПК, и с роутером в LAN. Новая строка действует сразу, без перезапуска
службы (ключ перечитывается на каждое соединение), прежние сразу получают отказ.

## Протокол

Кадр: `u32` (big-endian, длина) + данные. Рукопожатие (`secure.rs`): клиент шлёт `HPC1` и 16
случайных байт, служба — свои 16; из ключа строки и обоих чисел выводятся два ключа сессии
(SHA-256, по одному на направление). Дальше каждый кадр — protobuf `ControlMessage`,
зашифрованный ChaCha20-Poly1305, nonce шифра — номер кадра в своём направлении: подмена,
повтор или перестановка кадров ломают тег. Первое зашифрованное сообщение клиента — `Hello {
version }`: служба не может его расшифровать — ключ другой, соединение закрывается (в журнал
— «чужой ключ», сам ключ не пишется). Ответ `Welcome` доказывает клиенту, что и служба знает
ключ. Шифр и хеш — те же, что у подписи дыр (`connection::auth`), поэтому на роутере новых
зависимостей нет. Дальше:

| Запрос | Ответ |
|---|---|
| `GetStatus` | `Status`: режим, `BIND_ADDR`, время работы, трафик моста, пиры (имя, состояние, живые дыры, адреса в туннеле, дыры с адресом пира, счётчиками и потерями в обе стороны, «ждёт первого подключения», можно ли удалить, последняя регистрация пира на MQTT-брокере — внешний адрес и время по часам пира; видно, доходит ли телефон до брокера, даже когда дыры не пробиваются) |
| `Subscribe { interval_ms }` | служба сама присылает `Status` раз в `interval_ms` (трей — раз в секунду), пока соединение открыто |
| `CreatePairing` | `Pairing { bundle, uri, name }` — пакет сопряжения нового телефона |
| `RemovePeer { name }` | `Done` или `Error` |

Полные GUID в статус не попадают — только имена (первая группа GUID): полный GUID — секрет пары.
Номера 5–8 и 11 (`Event`, `Identity`, `SetPeer`, `Restart`) зарезервированы в замысле.

**Потери** считаются по обмену `Stats` между пирами (раз в 10 с): пир сообщает, сколько по
дыре отправил и получил, служба сравнивает со своими счётчиками на момент отчёта. Меньше 20
пакетов по дыре — оценки нет («—»).

**Где слушает служба.** `hp-server` — `127.0.0.1:47001` по умолчанию (`CONTROL_ADDR`, `off` —
выключить). `hp-router` — только если задан `CONTROL_ADDR`, и только адрес LAN (`0.0.0.0` не
принимается): порт управления не должен быть виден из WAN. Шифрование закрывает канал от
соседей по LAN и Wi-Fi (гостей с паролем от сети, ARP-спуфинга): без ключа не прочитать ни
статус, ни пакет сопряжения с полными GUID телефона и не отправить команду. От перебора ключ
защищён длиной (256 бит); от того, у кого есть строка подключения, — ничем: строка — секрет,
при утечке выпускается новая.

## Сопряжение

«Добавить телефон» (трей) или `hpctl pair`: служба генерирует новую пару GUID (свой и телефона),
сразу поднимает для неё набор дыр и отдаёт пакет:

```proto
message PairingBundle {
  uint32 version = 1;
  string pc_guid = 2;        // GUID службы — PEER_ID телефона
  string phone_guid = 3;     // GUID телефона — MY_ID телефона
  string stun = 4;           // ip:порт[,ip2:порт]
  string mqtt = 5;           // ip:порт, TLS
  bytes mqtt_ca_pem = 6;     // ca.crt брокера
  reserved 7;                // было: конфиг WireGuard
  uint64 expires_unix = 8;
}
```

QR — ссылка `homeproxy://pair?d=<base64url(PairingBundle) без =>` (~1 КБ; уровень коррекции M,
поле 4 модуля). Её же можно открыть как deep link. Адрес в туннеле и DNS в пакет не входят:
телефон получает их от службы при подключении (`AddressRequest`/`AddressAssign`).

Внутри — полные GUID пары, из них выводятся все ключи, поэтому пакет — **секрет**: показывается
только по кнопке, не логируется и не пишется на диск; трей стирает картинку при закрытии.

Жизненный цикл на стороне службы (`hp-server/src/service.rs`):
- ожидающий телефон — не больше одного: повторное «Добавить телефон», пока он не подключился,
  выдаёт тот же пакет с продлённым сроком (10 минут), лишние наборы дыр не копятся;
- первая живая дыра — телефон сопряжён: пара дописывается в `peers.state` (права 600) и
  поднимается при каждом запуске;
- срок вышел, а телефон не пришёл — набор дыр останавливается;
- `RemovePeer` — набор дыр останавливается, адреса телефона освобождаются в мосту, пара
  стирается из `peers.state`. Пиров из `server.env` так удалить нельзя — только там.

У `hp-router` так же, только телефону ещё выдаётся свободный номер (`client_id`, 1–255),
сопряжённые хранятся в `phones.state` (`номер GUID-роутера GUID-телефона`), адрес в туннеле
телефону выдаёт VPS, а в статусе первым идёт VPS (шлюз дома).

`hp-server` может стартовать вообще без пиров (без `MY_ID`/`PEER_ID`): поставил, открыл трей,
добавил телефон.

## Трей (`hp-tray`)

```
hp-tray [--connect строка-подключения] [--config файл-настроек] [--hidden]
```

- при первом запуске — экран «Подключение к службе»: вставить строку (ПК: `hp-server
  --connection-string`; роутер: LuCI); `--connect` — то же из командной строки;
- кнопка «Служба…» — добавить ещё одну службу (окно показывает все сразу, у пиров подпись службы; значок — по худшей) или заменить строку той же службы после смены ключа; строки лежат в `tray.conf` по одной в строке, убрать службу — удалить строку и перезапустить трей; `--config файл` — отдельный набор служб;
- `--hidden` — не показывать окно при старте (автозапуск): окно открывается из значка.

Окно: цветная точка и заголовок («На связи телефонов: 1 из 1»), режим, `BIND_ADDR`, время
работы, трафик моста (при нескольких службах — по строке на каждую); карточка на каждый телефон (состояние, `живые/цель` дыр, адрес в туннеле,
средние потери ↑ к телефону и ↓ от него; по щелчку — таблица дыр: адрес телефона, отправлено,
получено, потери, цвет — по худшим потерям: до 2 % зелёный, до 10 % жёлтый, дальше красный;
кнопка «Удалить телефон» с подтверждением). «Добавить телефон» — экран с QR и отсчётом срока;
когда телефон подключится, подпись станет зелёной.

Значок: серый — нет связи со службой, красный — ни один телефон не на связи (или роутер без связи с
VPS), жёлтый — телефонов
нет или в работе меньше четырёх дыр, зелёный — у всех в работе не меньше четырёх дыр (набор
динамический, 4–10; «11/10» бывает). При нескольких службах значок — по худшей, служба без связи
красная. Подсказка — телефоны и дыры. Меню:
«Открыть», «Добавить телефон», «Выход». Закрытие окна прячет его в трей.

Устройство:
- окно — Slint (`ui/main.slint`), `winit` + программный рендер: работает без GPU (ВМ, RDP);
  тема — светлая или тёмная, как в системе;
- значок: Linux — `ksni` (StatusNotifierItem по D-Bus, без GTK; KDE, XFCE, GNOME с расширением
  AppIndicator), Windows — `tray-icon`;
- сеть — tokio в фоновых потоках: подписка на статус (переподключение каждые 2 с) и отдельные
  соединения на команды; интерфейс обновляется через `upgrade_in_event_loop`, строки списка — на
  месте (иначе Slint пересоздаёт карточки и сбрасывает их состояние);
- QR — крейт `qrcode`, картинка рисуется в памяти.

Размер: ~21 МБ на Linux (без отладочной информации), ~14 МБ на Windows — почти всё Slint и winit.

## Проверено

- Linux (KDE Plasma, Wayland и X11): служба без пиров → трей → «Добавить телефон» (из меню
  значка через D-Bus) → QR с отсчётом → `hp-client` на VPS с GUID из пакета → «подключён», 10/10
  дыр; перезапуск службы — телефон поднимается из `peers.state`; таблица дыр с потерями под
  трафиком; удаление с подтверждением (сокеты набора закрываются, телефон теряет дыры); служба
  остановлена — серый значок и «Нет связи со службой».
- Windows 10: сборка `hp-server`, `hp-tray`, `hpctl`; протокол управления (`hpctl status`,
  `pair`) против `hp-server.exe` с полным туннелем OpenVPN. Окно и значок на Windows вживую не
  проверялись: на тестовой ВМ нет интерактивного сеанса.
- Роутер (Xiaomi 4C, OpenWrt 23.05): `hp-router` под procd, трей с ПК к LAN роутера — первая
  вставка строки, VPS и телефоны в окне, сопряжение телефона через роутер (адрес выдал VPS),
  новая строка из LuCI-команды — старая сразу отвергнута, новая принята без перезапуска трея;
  права LuCI проверены сессией rpcd. Сама страница LuCI в браузере не открывалась (нужен пароль
  роутера).
- Тесты: `cargo test -p hp-control` (кадры, base64url, ссылка, строка подключения, шифрованный
  канал: чужой ключ, подмена номера кадра), `-p hp-server --test control` (ключ, смена ключа без
  перезапуска, статус, подписка, ошибки), `-p hp-router` (адрес управления только LAN, флаги),
  `-p hp-tray` (форматирование, уровни, значок).
